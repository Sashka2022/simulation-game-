# משחק חי וסנכרון ב־Vercel

## מה השתנה

הפריסה המלאה מריצה Next.js עם API פרטי ו־PostgreSQL משותף. המשתתפות אינן צריכות חשבון. כל משתתפת מקבלת הרשאה מוגבלת למשלחת שבחרה; אישור מנחה הוא מצב אופציונלי. קוד ההצטרפות ו־QR אינם הרשאות ניהול. מסך ההקרנה משתמש בקישור ציבורי נפרד; אפשר להעתיק אותו מתוך ממשק המנחה ולפתוח במכשיר אחר.

`DATABASE_URL` נבדק בצד השרת בלבד. `POSTGRES_URL` נתמך כחלופה. בפריסת Vercel אין fallback ל־SQLite זמני: אם החיבור חסר, מתקבלת הודעה נגישה והדגמה עדיין זמינה. בהרצה מקומית ללא משתנה חיבור, SQLite נשאר זמין לצורכי פיתוח.

## חיבור Neon לפרויקט הקיים

1. ב־Vercel פתחי את `simulation-game` → **Storage** → מסד Neon שיצרת.
2. בדקי שהפרויקט מופיע ב־**Connected Projects**.
3. ב־**Settings → Environment Variables** בדקי את **שם** המשתנה `DATABASE_URL`, ואת הסביבות שלהן הוא משויך. אין צורך להציג או להעתיק את הערך. להפעלה הראשית יש לסמן **Production**; לבדיקת הענף גם **Preview**.
4. פרסי את הקוד החדש מענף `feat/live-sessions` כ־Preview, או לאחר שילובו ב־`main` כ־Production. אם הפריסה נוצרה לפני חיבור המסד, בחרי **Redeploy**.
5. `vercel.json` מגדיר Framework `Next.js`, Build `npm run build`, Output `.next`, Install `npm ci`. הסירי Dashboard Overrides ישנים ל־`build:demo` או `dist-demo`, אם קיימים. Node.js: ‏24.x.
6. אין צורך לפתוח SQL Editor: הגישה הראשונה לשרת יוצרת טבלאות ואינדקסים אוטומטית, תחת נעילת אתחול משותפת. השתמשי בכתובת pooled של Neon שסיפקה האינטגרציה.

לא מבקשים סיסמה בצ׳אט. לא מגדירים חיבור למסד עם `NEXT_PUBLIC_`. חיבור מרוחק מצפין את התעבורה ומאמת את תעודת השרת. אין צורך להוסיף מפתח של Supabase או שירות AI.

## איך מנהלים מפגש משותף

- **מנחה:** בכתובת הראשית, בחרי ״פתיחת חדר מצב״, הזיני שם ושמרי את קוד השחזור הפרטי. השאירי את הדפדפן הזה פתוח.
- **משלחות:** סורקות את ה־QR או פותחות את אותו אתר, בוחרות ״כניסה למפגש״ ומזינות את קוד המפגש. כל משתתפת מזינה שם או כינוי ובוחרת אחת מחמש המשלחות לפי הספירות המוצגות.
- **ניהול:** המנחה יכולה להוסיף, להסיר ולהעביר משתתפות, למנות נציגות, לנעול הצטרפות/מעברים או להפעיל מצב אישור מתוך ״ניהול משתתפות״ בכל שלב.
- **מקרן:** המנחה פותחת מסך הקרנה באותו מחשב, או לוחצת ״העתקת קישור למקרן״ ופותחת אותו במחשב המחובר למקרן. אין לשלוח קישור מנחה למשלחות.
- **משחק:** המנחה שולטת בשלב ובשעון. עמדות המשתתפות, הסכמות והתחייבויות נשמרות במסד ומופיעות במכשירים האחרים. המקרן רואה רק התחייבויות שפורסמו במפורש.
- **המשך אחרי ניתוק:** באותו מכשיר ובאותו דפדפן פותחים שוב את קישור המפגש. אין צורך לבחור מחדש משלחת. מכשיר חדש יוצר זהות חדשה; אפשר להסיר את הזהות הישנה דרך המנחה.
- **הדגמה:** ״להתנסות במשחק״ נשאר מצב מקומי. הוא אינו מסנכרן בין מכשירים, גם באתר המלא.

הסנכרון מתבצע בקריאת מצב מורשית כל כשתי שניות, ולא ב־WebSocket. בחזרה ללשונית או לרשת נשלחת קריאה מיד. אין התחייבות לעדכון מיידי ברשת חלשה; אישור שמירה יופיע רק לאחר אישור השרת.

## עמידות והרשאות

- מצב המשחק, יומן ההחלטות והגרסאות נשמרים בעסקה אחת, תחת `SELECT … FOR UPDATE`. שתי פונקציות Vercel אינן יכולות לדרוס זו את זו.
- UUID של פקודה נרשם בקבלה ייעודית. ניסיון חוזר אחרי timeout לא מכפיל החלטה.
- הסכמות מתייחסות לגרסה מדויקת. כתיבה מול גרסה ישנה נדחית ומשאירה את הטיוטה לשימוש חוזר.
- כל משלחת יכולה לכלול מספר משתתפות משתנה, ללא מכסת גודל בקוד. כל קריאה וכתיבה בודקות את זהות המכשיר ואת שיוכו למפגש.
- בקשות טיוטה שמגיעות בסדר הפוך אינן דורסות טיוטה חדשה יותר ב־PostgreSQL.
- שחזור מנחה מחליף את הרשאת המנחה ואת קישור ההקרנה; הרשאות ישנות אינן ממשיכות לעבוד.
- מידע חסוי אינו מגיע לתשובות ה־API של משלחת אחרת או של המקרן. גם פתיחת המקרן בדפדפן המנחה מחזירה רק תוכן ציבורי.
- שגיאות חיבור למסד מוצגות באופן כללי; כתובות חיבור, SQL וסיסמאות אינם מוחזרים לדפדפן.

## שמירה ומחיקה

המנחה יכולה למחוק מפגש. המחיקה מסירה גם חברויות וקבלות פקודות באמצעות קשרים מדורגים במסד. מפגשים בני יותר מ־30 יום אינם נגישים, ומסולקים בניקוי בעת יצירת מפגש חדש. אין משימה יומית מתוזמנת בפריסה זו; למחיקה פיזית בדיוק במועד נדרש מנגנון תזמון אצל מפעיל האתר. גם גיבויים כפופים למדיניות שמירה נפרדת.

## בדיקת הפעלה אחרי הפריסה

1. פתחי `/api/status` — תקין: `liveAvailable: true`.
2. פתחי מפגש במחשב והצטרפי מהטלפון בשם/כינוי ובמשלחת שבחרת; ודאי כניסה מיידית.
3. התחילי משחק ובדקי שהטלפון עובר לאותו שלב בתוך מספר שניות.
4. בחרי עמדה בטלפון ובדקי שהיא מופיעה אצל המנחה.
5. רענני את הטלפון ופתחי מקרן בדפדפן נפרד. בדקי שהמצב נשמר ושמידע חסוי אינו מוקרן.

בדיקות אוטומטיות מול PostgreSQL אמיתי כלולות ב־`npm run test:postgres` ובבדיקות הדפדפן. אין להסיק מהן שהחיבור למסד בחשבון Vercel של המשתמשת אומת מתוך סביבת הפיתוח.

הגדרות חברות, הרשאות לאחר מעבר ומגבלות קיבולת: [משלחות פתוחות](open-delegations.md).
